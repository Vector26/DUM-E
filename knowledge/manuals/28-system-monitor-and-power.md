## What it is
The system monitor is a set of small Python tools that show machine health in plain English. [V] (src: library/10-system-monitor/README.md:1-3)
`sys-check` prints a one-shot health card. `plaintop` is a full-screen live monitor. [V] (src: library/10-system-monitor/README.md:7-10)
A background user service logs CPU, GPU and UPS power every 5 minutes into a SQLite file. [V] (src: power_logger.py:1-6,15)
`fortress-vitals` is a separate Go terminal dashboard for host, Docker, GPU and Ollama. [V] (src: homelab/monitoring/cmd/fortress-vitals/main.go:1-28)
The power functions in `~/.bashrc` change CPU governor, turbo boost, GPU power limit and can unload the NVIDIA driver. They use `sudo`. [V] (src: ~/.bashrc:190-453)

Power functions (from `~/.bashrc`). All use `sudo` except `powerstatus`. [V] (src: ~/.bashrc:200-453)

- `powersaver` — MUTATES. Exactly: [V] (src: ~/.bashrc:200-270)
  1. CPU governor to `powersave` via `sudo cpupower frequency-set -g powersave`, or `sudo tee /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor` if `cpupower` is missing. (`cpupower` is installed: `/usr/bin/cpupower`.) [V] (cmd: command -v cpupower)
  2. Turbo boost off: `echo 0 | sudo tee /sys/devices/system/cpu/cpufreq/boost`.
  3. If NVIDIA modules are loaded: counts compute apps with `nvidia-smi --query-compute-apps=pid`. It also treats a display session as "in use", but only when `$DISPLAY` is set.
  4. If anything counts as in use: `sudo nvidia-smi -pl 250 -pm 0` (power limit 250 W, persistence off).
  5. Otherwise: `sudo modprobe -r nvidia_uvm nvidia_drm nvidia_modeset nvidia` (unloads the NVIDIA driver). If unload fails it falls back to `sudo nvidia-smi -pl 250 -pm 0`.
- `powersaver-lite` — MUTATES. CPU governor `powersave`, turbo off, `sudo nvidia-smi -pl 250`, `sudo nvidia-smi -pm 0`. Does not unload the driver. [V] (src: ~/.bashrc:363-400)
- `powersaver-force` — MUTATES. CPU governor `powersave`, turbo off, then `sudo modprobe -r nvidia_uvm nvidia_drm nvidia_modeset nvidia` with no safety checks. May break the display. [V] (src: ~/.bashrc:326-361)
- `performance` — MUTATES. If NVIDIA modules are not loaded: `sudo modprobe nvidia nvidia_modeset nvidia_drm nvidia_uvm`. Then CPU governor `performance`, turbo on (`echo 1 | sudo tee …/boost`), `sudo nvidia-smi -pl 300`, `sudo nvidia-smi -pm 1`. [V] (src: ~/.bashrc:272-324)
- `powerstatus` — READ. Reads `/sys/devices/system/cpu/cpu0/cpufreq/scaling_governor`, `/sys/devices/system/cpu/cpufreq/boost`, `/sys/devices/system/cpu/cpu0/cpufreq/scaling_cur_freq`, `lsmod`, and `nvidia-smi --query-gpu=name,power.draw,power.limit,clocks.gr,clocks.mem,temperature.gpu`. No sudo. [V] (src: ~/.bashrc:402-453)
- All power settings are volatile. They reset on reboot. [V] (src: POWER_COMMANDS.md:110-118,220-223)

Live power state at 2026-10-29 ~22:35: governor `powersave`, boost `1` (on), GPU power limit 300 W (min 250 W, max 300 W), persistence mode Disabled, GPU draw 15.2 W. [V] (cmd: cat scaling_governor, boost; nvidia-smi --query-gpu=…power.limit,power.min_limit,power.max_limit,persistence_mode)

## Known problems and fixes
- **CPU power is never recorded.** Symptom: CPU Wh is always 0; CPU power shows "N/A". Cause: `/sys/class/powercap/intel-rapl:0/energy_uj` is mode `0400 root`, so the user service cannot read it. Also `power_uw` does not exist on this host. Evidence: 0 of 50,322 rows have `cpu_energy_uj > 0`. [V] (cmd: ls -la /sys/class/powercap/intel-rapl:0/; sqlite3 -readonly … sum(cpu_energy_uj>0)) Fix: the owner decides. Options: a udev rule or root service that makes `energy_uj` readable, or accept GPU+UPS only. DUM-E has no action for this; the owner runs: a sudo change of his choice.
- **Wrong counter wrap.** `collectors.py` adds `2**32` when the energy counter goes backwards. The real wrap value is `max_energy_range_uj` = 65,532,610,987. Totals would be wrong after a wrap if CPU energy were ever recorded. [V] (src: collectors.py:481-482; cmd: cat max_energy_range_uj)
- **"Total" switches meaning.** When UPS energy exists, "total" is the UPS (wall) energy, not CPU+GPU. [V] (src: collectors.py:510-512)
- **The logger calls sudo every 5 minutes.** `sudo -n pwrstat -status` appears in the user journal every 5 minutes. This is noise in the auth log, not a failure. [V] (cmd: systemctl --user status system-monitor-power.service)
- **`sys-check` alias uses system python3.** System python has `rich` but no `psutil`. [V] (cmd: ls /usr/lib/python3/dist-packages | grep -i psutil → nothing) Then CPU usage and RAM show N/A and disks are empty. [I] (src: collectors.py:13-16,108-111,223-227) `install.sh` did not fix the alias because it skips when "sys-check" is already in `.bashrc`. [V] (src: install.sh:41-48) Fix: the owner edits `~/.bashrc:131` to use `~/homelab/system-monitor/.venv/bin/python`. DUM-E has no action for this.
- **`fortress-vitals` alias comment is wrong.** The comment says "in tmux". The source has no tmux code. It opens a full-screen terminal UI. [V] (src: ~/.bashrc:487,490; grep tmux in source → none)
- **fortress-vitals binary may be older than its source.** Binary 2026-03-23; `main.go` 2026-04-17. [V] (cmd: ls -la) Whether behaviour differs is [U]. Rebuild: `cd ~/homelab/monitoring/cmd/fortress-vitals && go build -o ~/bin/fortress-vitals .` (src: README.txt). MUTATES (overwrites the binary). Owner only.
- **`powersaver` safety check is weak.** It only counts CUDA compute apps. It only checks the display when `$DISPLAY` is set. Over SSH `$DISPLAY` is usually empty, so the display check is skipped. [V] (src: ~/.bashrc:226-239) [I] that over SSH it can try to unload the driver while a desktop session uses the GPU.
- **`powersaver` stops the AI brain path.** Unloading the driver kills access to the GPU. The llama server on :8081, Ollama, and GPU containers (for example `cine_broll_worker`) would fail or fall back. [I] (src: DUM-E.md sections 2, F1) While llama-server holds the GPU, `powersaver` falls back to 250 W instead. [I] (src: ~/.bashrc:241-247)
- **POWER_COMMANDS.md says "Intel RAPL" `power_uw` watch command.** That file does not exist on this host. The watch example in the doc prints nothing for CPU. [V] (src: POWER_COMMANDS.md:129; cmd: ls intel-rapl:0)
- **POWER_COMMANDS.md says `powersaver-lite` saves "~30-40%".** These numbers are from the doc, not measured. [U]
- **The power DB grows forever.** About 1.9 MB after 9 months. Low risk. [V]
